## 本轮发现并修复

1. **真实规划超过协调层期限。** 原专业线程没有继承请求的 ContextVar 缓存，十次读取会发送十次完整云快照请求，额外的身份读取也重复执行。给每次专业调用建立独立的 repository scope 后，十次读取只发送一次快照请求；不复用调用者或下次任务的身份缓存，提交后仍使缓存失效。30 秒协调期限和超时后的失败阻断保持有效。修复后的真实规划 HTTP 请求约 22.73 秒完成；课程服务仍可能超时，不能保证未来延迟。
2. **有历史记录的云快照被截断。** 普通 4,000,000 字节读取上限在本轮 4,914,021 字节真实快照上截断 JSON，导致所有后续业务读取报 CLOUD_UNAVAILABLE。服务端专用 snapshot RPC 改为有界 32,000,000 字节；其他端点及非管理员调用保持原上限。均多读一个字节以明确识别超限，提示管理员检查存储。没有删除历史或放宽认证。这是教学单实例的容量边界，分页/生产扩容仍未实现。

原超时案件保留 HUMAN_ASSISTANCE，没有补写为成功。受限恢复请求曾在数据库已保存 AWAITING_HUMAN_APPROVAL 后，因快照截断而无法返回页面；修复后从实际状态继续审批，没有重复派发或重建该案件。

## 小组演示操作顺序

1. 按 [初始化说明](DEMO_ACCOUNTS.zh-CN.md) 准备环境、`.env` 和专用账户。已有账户的登录资料只在本地忽略的 `.demo-accounts.local.json`；不要提交或打包该文件。其他机器需使用团队批准的资料提供方式，或独立 namespace；不覆盖原身份。
2. 连接校园网络/VPN，再执行 `.venv/bin/python scripts/start_demo.py`。Windows 使用 `.venv\Scripts\python.exe`。预检不通过时按提示处理，不能将跳过模型探测写成真实模型成功。
3. Supplier `/supplier` 说明报价来源；Operator `/admin` 对普通报价执行 Pass。过期、零库存例子用于展示拒绝，不能用于正常规划。
4. Traveller `/app` 确认草稿并开始处理；Operator 审核响应，Operations 交付后旅客比较、勾选采用。可先开始行程，再修改预算，展示 Active 修订及旧版本保留。
5. 旅客对 Active 行程提交取消请求；Operator 在该案记录模拟取消证据。按 [Exception 门户流程](../exception/PORTAL_INTEGRATION.zh-CN.md) 继续，展示审核、选择以及受限决定的独立批准。
6. 重启服务后需重新登录；检查 My trips、原版本、调查和轨迹。会话重新登录不等于业务数据丢失。再演练时使用新 scenario 保留历史，不清库。

Stage 1 对应：UC-01/02 的已确认需求、方案比较和明确采用；UC-03 与 AD/SD-03 的 Active 行程、可信证据、Supplier/Planning 协作和受控恢复建议；UC-05 以及共享审核要求对应身份、版本、批准、轨迹与失败阻断。报告允许模拟业务数据，本轮真实的是认证、存储与模型调用。
