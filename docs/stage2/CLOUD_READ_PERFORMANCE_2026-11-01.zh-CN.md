## 本次修改

- Planning 的版本、选择指针和采用指针改用现有按 ID 的私有读取 RPC。采用事务内仍读取已绑定的未提交记录，保持原子性。
- Supplier 当前报价改为按报价指针及版本读取，保留失效指针隐藏报价/价格/结果的行为。
- 对只读的私有 `tripmate_state` 查询，遇到 SQLSTATE `57014` 时最多重试一次；再次取消仍报错。认证、业务提交和其他 RPC 不重试。响应大小上限与数据库版本检查保持有效。
- 不需要新增数据库迁移或调整数据库超时设置。

## 同一数据的只读云端对比

旧 ZIP 与优化代码分别顺序执行三轮相同操作，以下为后端服务耗时中位数，不含网页登录和页面渲染。每次都断言没有业务提交；行程和报价完整结果摘要相同，会员资格、层级及行程数量相同。会员决策 ID 和时间仍按查询重新生成。

| 操作 | 原版 | 优化后 | RPC JSON 数据量，原版 → 优化后 |
| --- | ---: | ---: | ---: |
| 会员概览 | 7.096 秒 | 3.273 秒 | 8.55 MB → 0.55 MB |
| 单个行程版本 | 4.203 秒 | 0.417 秒 | 8.00 MB → 33.4 KB |
| 当前供应报价评估 | 7.332 秒 | 2.098 秒 | 8.01 MB → 14.8 KB |

上述三个只读操作的完整事务快照读取均从每次一次降为零。数据量按 RPC 返回对象的紧凑 JSON 编码估算，不含认证响应与 HTTP 开销。样本量小且受云服务负载影响，不代表所有请求的固定耗时或生产 SLA。业务写入仍需要一致性快照。
