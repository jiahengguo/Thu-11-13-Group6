# 云端会员查询与规划超时修复

## 实际复现

- 原版完整回归 351/351、前端 15/15、十项隔离恢复验收通过。四个真实演示账户均可登录；四项模拟报价实际提交、处理并由 Operator 审核。
- 真实规划请求约 44.55 秒后返回 `HUMAN_ASSISTANCE / LLM_TIMEOUT`，没有交付方案。协调层保存超时结果，把数据库版本从 477 更新至 478；后台规划线程随后使用 477 提交，被 `PT409 / TRIPMATE_CONCURRENT_CHANGE` 拒绝。用户提供的 Supabase 20:38:08 日志与该提交对应。

- 本轮尚未重新复现早先初始化的 `CLOUD_UNAVAILABLE`。本补丁不声称已解决所有云服务可用性问题。

## 修改

1. `MEMBERSHIP` 概览仍检查身份并重新计算当前会员资格，但不写入业务状态。地图、无广告和会员优惠等受保护动作保留审计和即时资格检查。
2. Supplier 查找可用报价时，一次读取案件状态，替代逐报价请求；撤回报价的排除规则保持有效。
3. 启用真实模型规划的门户使用 60 秒专业任务等待上限，覆盖云查询、模型调用和保存。其他服务默认仍为 30 秒；模型自身 25 秒调用超时及有限修复次数保持有效，超时仍转人工。
4. 专业线程超时后设置取消标记。云仓库在发起新的提交前检查该标记，拒绝晚到保存。已在传输中的请求无法撤回，仍由数据库版本检查保护；没有取消版本检查或重试业务写入。
