# 默认门户的课程模型规划接线

对应 WN5620-54 的接线部分，复用既有 ModelPlanningEngine、CampusClient、Supplier 查询、PlanningValidator、共享 Reviewer 和私有 Planning 存储。启动脚本现在明确启用模型规划；直接启动服务器时可使用：

```sh
.venv/bin/python -m tripmate.portal.server --demo-pricing --model-planning
```

模型只收到已确认的旅行需求、当前合格报价的售价和行程属性，提出报价 ID 组合。客户账号、邮箱、密码和供应商成本不发给规划模型。确定性工具计算总价并检查完整项目、预算、时间、库存和其他约束；无效组合最多反馈修复三轮。有效结果才交共享 Reviewer 和 Operations 外发审核，模型不能决定批准或采用。

每次规划创建独立客户端/规划器，避免将上一次案件的尝试记录复用于下一案件；每次调用 20 秒超时、最多 1024 completion tokens。模型不可用、输出截断、虚构 ID 或持续无效时失败，不默默回退离线候选，也不把模型找不到方案解释成所有库存都不可行。配置缺失会阻止模型模式启动。

`start_demo.py --skip-model-probe` 仍启用上述真实模型路径，只跳过启动前探测；请求模型失败仍明确失败。直接服务器不带 `--model-planning` 则继续使用原确定性规划器，供明确的非模型调试使用，不得将这种结果表述为课程模型生成。

该选择依据 Stage 1 的 Agent 提案、工具校验和人工监督分工：复用已存在的有界循环，避免再引入框架或另建未集成聊天界面。供应数据准备仍采用结构化模拟事实，不需要模型替脚本编造供应商数据。

四项新增测试通过：模型组合经过实际门户业务服务校验并保存、隐私数据不进入模型输入、连接失败不回退、虚构报价有限修复后失败、缺配置阻止启动。模型传输是明确标记的测试替身；真实课程接口在 2026-10-27 05:00 续作中实际探测仍返回 `TOOL_UNAVAILABLE`。真实模型演示验收仍需课程服务/网络连通后执行，不能标为已完成。

最终完整回归：277 项全部通过，169.250 秒；包括既有认证、Supplier、Planning、Exception、审核、数据准备和必要失败场景。启动脚本/服务器帮助入口及 diff 检查通过。未制作 ZIP 或执行解压部署测试。
