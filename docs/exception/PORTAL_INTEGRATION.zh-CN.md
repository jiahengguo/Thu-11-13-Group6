# 默认认证门户 Exception 接入

当前验证边界（2026-10-27）：云/模型接口现已分别及联合预检通过，但本批取消恢复浏览器/HTTP 证据使用 FakeCloud，仍需真实云账户的一次连续业务验收。不要将组件连通或已保存内部建议视为完整恢复验收。见 [PR 验证审计](../stage2/PR_VALIDATION_AUDIT_2026-10-27.zh-CN.md)。

对应 WN5620-12/44/13/50/51/52 的基础恢复链路，依赖 PR #18/#19 以及初始化/就绪分支。并不代表这些工作项的全部验收或成员评审已完成。

## 本批流程

1. 旅客经现有 Planning 生成、审核交付并明确采用行程，再明确开始行程。
2. 旅客提交并确认该 Active 行程的取消事件。
3. Operator 在案件详情中记录受影响交通项目、模拟取消通知来源、有效期、已确认不可退成本、置信度，以及受限行动/法律/安全标记。旅客文本不会自动变成供应商取消事实。
4. 旅客开始处理。默认 Portal 已注册 Exception；它从当前所选行程与上述证据构造上下文，经现有 ProjectSupplier/ProjectPlanning 查询当前合格报价并生成完整恢复候选，保留客户确认的约束和未受影响安排。
5. 共享确定性 Reviewer 审核精确提案版本。受限提案需要单独人工决定；Operations 仍独立控制外发审核与交付。
6. 旅客看到审核交付后的建议，可明确选择某一建议或拒绝全部；选择后再审核和受控交付。交付建议不表示已改签、支付或恢复出行，案件继续开放。

## 存储与权限

- 使用现有私有 RPC 保存不可变调查快照，不新增公开数据访问。结果/审批/轨迹只有在 Operations 接收事务成功时才进入共享案件；失败导入通过 CloudRecords.savepoint 回滚。
- 云存储失败被转换为现有 runtime 的保存失败边界，不返回成功提案。
- 只有验证后的 Operator 能录入或查看内部调查依据；旅客仅看到已交付建议的成本、时间、条款与安排，不返回供应商成本、内部 Planning record 或未交付调查草稿。
- 证据变更撤销旧建议的展示/选择权限，要求重新确认并调查；保留历史版本，旧授权不沿用。
- 在审核/交付/选择时重新检查 Active 行程、当前所选 baseline、证据来源及证据作者权限；行程或依据变更时不释放旧提案。
- 撤回、重复请求、缺证据、低置信、法律/安全问题、无可行备选、过期证据均保留安全边界。

## 报告依据和实施选择

依据 Stage 1 UC-03、AD-03/SD-03、UC-05/UC-07 的身份、证据、完整方案、人工监督和受控通信要求。报告未规定具体证据录入页面；本批采用明确的 Operator 模拟通知表单，成本较低且不会从旅客声称推断供应商事实。

非退回成本由 Operator 明确确认输入，不自动推断退款或补偿。当前仍使用既有恢复成本算法（明确不可退成本加完整候选报价），输出成本口径，不擅自抵扣已支付费用。

本批只支持通过当前 Planning 保存并明确采用的基线；无法检索的旧任意行程要求补充材料。投诉入口会记录缺少证据/政策并要求澄清，不伪造投诉责任或已解决。自动提醒、等待截止、完整外部完成信号、daily 扩展及正式云端验收仍待后续。
