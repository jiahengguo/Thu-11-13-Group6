# Sprint 2：认证门户 Planning 接入

分支：`codex/sprint2-planning-portal-integration`。关联 WN5620-12、24，并推进 WN5620-6、11、19、54 的部分依赖。基于 main `d0717e4`；不表示四 Agent 发布、成员评审或所有关联任务已经完成。

## 本批实现

- 默认 Portal 注册 Planning，使用当前 `SupplierGateway` 返回的审核报价，不从演示目录偷偷补齐库存。
- 共享 Reviewer 根据当前已确认请求和供应商事实重新运行确定性校验，不使用工作台的 FixtureReviewer。
- Planning 的不可变版本、执行结果、所选版本及轨迹进入现有私有云记录；不增加公开表或客户端权限。
- 方案采用与 Operations 的生命周期、命令幂等、会员决定及审计记录共用一次提交，失败整体回滚。
- 审核交付后，旅客可查看推荐与备选方案、分项售价、时间、来源、条款和共同指标，明确勾选后采用。
- 已采用版本可带入修订表单；确认新要求后生成 successor，保留 baseline。比较展示需求变化、价格变化及报价版本/行程项目的前后差异。

## 报告依据与已确认决策

Stage 1 §3.3、UC-01、UC-02、AC-UC01-01–05、AC-UC02-01–04：硬约束先于排序，使用合格报价，独立审核，Operations 控制对外呈现，明确确认修改，版本不可覆盖。

2026-10-24，用户授权为集成演示建立模拟定价。采用报告对象图的示例：加价率 10%，最低差价 AUD 15，配置版本 `demo-2026-10-24`。该数值不是报告规定的全局商业政策。

```sh
python -m tripmate.portal.server --port 8780 --demo-pricing
```

须先按现有门户说明配置 Supabase 并应用现有 migration。`--demo-pricing` 显式覆盖本次进程的价格政策；不传该参数时仍使用既有环境配置，缺配置继续阻断定价。模型密钥不因演示价格自动产生；结构化模拟流程不代表真实模型连接已验收。最低差价失败的报价仍被拒绝，不会自动提高成本或放宽限制。

演示目录的 reset 只恢复隔离目录，不会生成已获人工审核的业务报价。供应商须提交完整模拟服务信息，Operator 审核后才能供 Planning 使用。
