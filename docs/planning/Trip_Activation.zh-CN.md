# Sprint 2：旅客明确开始行程

分支：`codex/sprint2-start-trip`，基于规划门户分支提交 `aa93ea4`，属于有依赖关系的第二个独立功能分支。关联 UC-07 激活检查、UC-03 Active 行程前置条件及 WN5620-12 的集成依赖。

## 用户确认的业务规则（2026-10-24）

Stage 1 的 UC-07 明确要求激活时复核会员权限，UC-03 要求受影响行程为 Active；报告和 SM-02 未明确激活触发方式。用户确认：

1. 由旅客明确点击“开始行程”，系统复核会员权限并记录状态变化。
2. 已 Active 的行程采用确认后的新修订版本时保留 Active，只更新所采用版本，不要求再次开始。

因此不根据日期自动激活，不把采用方案、方案审核通过或模拟预订当作出行已经开始。

## 行为

- “My trips” 对已采用且 Planned 的行程提供确认勾选及 “Start this trip”。
- `POST /api/operations/start-trip` 接受 `requestKey`、`versionId`、`confirmed: true`，身份仍来自验证后的会话。
- 只有旅客本人当前所采用的、已审核交付的版本可以开始；Operator 及其他用户不能代替确认，旧版本和未采用的候选不能开始。
- UC-07 使用当前会员资料、行程数量和日期检查 `START_TRIP`。拒绝时记录决定和原因，维持 Planned，返回 `started: false`，页面显示拒绝原因。
- 允许时，Active 状态、开始时间、会员快照、命令结果和审计记录一起保存。保存失败不留下半完成状态，同一请求可安全重试。
- 重复确认不重复记录激活；重建应用后保持 Active。Active 行程可以通过现有权限校验提交中断调查请求，Exception 默认处理接线仍待下一批完成。
- Active 行程采用 successor 时保留原开始时间和 Active。旧的历史已采用版本不能用新请求覆盖较新的当前版本。
- 审核状态与行程生命周期分开：不可变 ItineraryVersion 的正文不会因开始行程而改写。
